# Code of Conduct

## Our commitment

This project builds decision support for clinical settings where expertise is
scarce. That purpose sets the tone we want: careful, plain-spoken, and honest
about what is not known. Everyone who takes part should be able to do so
without harassment, whatever their background, nationality, first language,
level of experience, disability, appearance, age, gender identity, sexual
orientation, religion, or clinical seniority.

## What we expect

- Assume the other person is acting in good faith and is worth answering
  clearly.
- Give and accept criticism of the work without turning it into criticism of
  the person.
- Say what you actually measured. If you are guessing, say you are guessing.
- Write plainly. Many contributors and users read English as a second
  language, and a clear sentence helps more than a clever one.
- Respect a disagreement that ends unresolved. Not every question has an
  answer today.

## What is not acceptable

- Harassment, intimidation, or personal attacks, in public or in private.
- Sexualised language or imagery, and unwelcome attention of any kind.
- Publishing anyone's private information without their explicit permission.
- Sustained disruption of discussions or review.
- Dismissing safety concerns because they are inconvenient. This one is
  specific to this project and is treated as seriously as the rest.

## Clinical claims are held to a higher bar

Statements about what the system detects, how well it performs, or what a
user should do clinically are not matters of opinion. Support them with a
measurement, a citation, or an explicit statement that they are unverified.
Overstating performance in an issue, a pull request, or the documentation is
a conduct problem here, not only a technical one, because someone may act on
it.

## Scope

This applies in all project spaces, including issues, pull requests, commit
messages, discussions, and any private correspondence about the project. It
also applies when someone is representing the project elsewhere.

## Reporting

Report a concern privately to the maintainer through their GitHub profile, or
open a draft security advisory on the repository if you would rather the
report stay private. Reports are handled confidentially. If a report concerns
the maintainer, and you would rather not raise it with them directly, GitHub
Support can act on the Community Guidelines independently.

Because this project currently has a single maintainer, there is no committee
to escalate to. That is a real limitation and worth knowing before you report.

## Enforcement

Responses are proportionate, and may include a private correction, a public
correction, temporary exclusion from a discussion, or a permanent block.
Whoever handles a report will say what they decided and why.

This code of conduct follows the spirit of the Contributor Covenant, adapted
for a small clinical research project.
